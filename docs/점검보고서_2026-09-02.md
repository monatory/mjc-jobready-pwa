## 2. 명단 화면 개선 (요청 ①)

### 원인

상담사 명단은 최대 15열(기본 12 + 연락상태·외부연계·취업)인데, 표의 자연 폭이 **1265px**(최악 조건
데이터 기준)인 반면 화면 가용 폭은 1440px 모니터에서도 **1210px**뿐이었음. 즉 어떤 화면에서도 잘렸음.
`.admin`이 `max-width: 1440px`로 묶여 넓은 모니터를 활용하지 못한 것이 핵심.

### 조치 (글자 축약·줄바꿈 없음 — 값은 그대로)

| 항목 | 변경 |
|---|---|
| 레이아웃 폭 | `.admin` max-width 1440 → **1760px**, 사이드바 230 → 210px, 본문 여백 24 → 18px |
| 명단 표 밀도 | 명단 전용 클래스 `.admin-table--list` 신설 — 셀 여백·배지만 축소(글자 자르지 않음) |
| 화면별 자동 단계 | 기본 0.8rem / 1439px 이하 0.75rem / 1279px 이하 0.73rem 3단계 |
| 카드 여백 | `.table-wrap--list`로 명단 표만 여백 축소 |
| 메뉴 접기 | `useSidebarFold` — 좁은 화면에서 사이드바 210px를 회수, 선택은 브라우저에 기억 |

### 실측 결과 (브라우저 계측)

| 화면 폭 | 표 필요 폭 | 가용 폭 | 가로 스크롤 |
|---|---|---|---|
| 1280px | 1032 | 1032 | **없음** |
| 1366px | 1118 | 1118 | **없음** |
| 1440px | 1108 | 1230 | **없음** (여유 122px) |
| 1440px · 메뉴 접기 | 1242 | 1242 | **없음** |

행 높이도 43px → 37px로 낮아져 한 화면에 보이는 학생 수가 약 20% 증가함.
밀도 규칙은 명단 표에만 적용되며 추천활동·기관·계정·학과별 현황 표 4종은 영향 없음(선택자 범위 확인).

## 3. 점검 방식

```
1단계 조사   10개 관점 병렬 (학생 흐름 / 관리자 / 상담사 / 추천활동 / 판정엔진 /
             보안 / CSV·통계 / 동시성 / UI·반응형 / 문서·배포)
2단계 검증   발견 건마다 독립 에이전트가 "이건 결함이 아니다"를 기본 입장으로 반박 시도
             → 코드로 반박되지 않은 것만 확정 (59건이 이 단계에서 기각됨)
3단계 완결성 "무엇을 놓쳤는가" — 위 관점이 건드리지 않은 파일·경계·생애주기 점검
```

반박 기각 59건의 주요 사유: 이미 방어 코드가 있음 / 시나리오가 도달 불가 / 코드 주석·명세에
의도로 명시됨 / 심각도 과장. 즉 **확정 34건은 반박을 견딘 것만 남은 결과**임.

## 4. 수정 완료 (17건)

### 4.1 치명적 — 오늘 만든 회귀

**STU-01 · 제출 실패 시 무한 자동 재제출 루프** (`src/student/Result.tsx`)

- 원인: 추천 Master 연동을 붙이며 제출 effect 의존성에 `analysis` 객체를 넣었는데,
  `getSurvey()`/`getDiag()`가 호출마다 새 객체를 반환해 참조가 매 렌더 바뀜 →
  effect가 매 렌더 재실행 → 제출 실패 시 `FAIL ↔ SAVING` 무한 반복.
- 증상: 학생 화면에 "제출 중…"이 사실상 영구 표시되고 실패 배너·재시도 버튼이 한 프레임만 보임.
  네트워크가 끊긴 학생은 화면을 닫을 때까지 계속 쓰기를 시도함(모바일 데이터·쿼터 소모).
- 수정: 세션 읽기를 **마운트 1회로 고정**(`useMemo`)해 참조를 안정화 + effect 의존성을
  `analysisReady` 불리언으로 교체. 재방문 시 자동 재제출은 그대로 동작(마운트마다 다시 읽음).
