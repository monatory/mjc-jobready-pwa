## 2. 사용자 요청 5건

| # | 요청 | 원인 | 조치 |
|---|---|---|---|
| 1 | 진학·창업 Route 표기 시 Level이 안 보임 | Route 템플릿 제목이 Level 제목을 **대체** | Level 제목 항상 표시 + Route 제목은 부제. 판정(비취업 Route = L2)은 무변경 |
| 2 | 갤럭시 S23 등에서 진단 "보통이다" 등 글씨 미표시 | 380px 이하에서 가운데 3개 라벨을 숨기던 CSS(의도적 축약)가 360px 폰에서 오류로 보임 | 5개 라벨 전부 표시(0.66rem·줄바꿈 허용). 360px 계측: 5개 block, 가로 넘침 0 |
| 3 | 마스터가 기존 학생 자료 삭제·보완 (9/7 전 테스트 응답 정리) | 응답 삭제 기능 부재(STU-04) | 상세 모달 "응답 삭제" + 명단 "필터 결과 N건 삭제"(실시일 기간으로 범위 지정, "삭제" 타이핑 확인). 응답+상담 기록 배치 삭제, 다학기 응답이 남으면 상담 기록 보존. 마스터·실측 모드 전용. "보완"은 기존 정보 수정 기능 |
| 4 | 같은 학번·이름·휴대전화 중복 등록 방지 방안 | 같은 학번은 이미 덮어쓰기(중복 불가). 실제 위험은 **학번 오기입 재응시** | 명단 "⚠ 중복 의심" 칩·배지·상세 안내 — 휴대전화 동일 / 성명+학과 동일인데 학번이 다른 응답. 자동 병합 없이 학번 교정·삭제로 정리. 학생 STEP 2 학번 칸 안내 1줄 |
| 5 | 결과지 "상담 신청" 버튼 → 상담 희망으로 저장 (이중장치) | 버튼이 안내 팝업만 띄움 | 클릭 시 `counsel_request:{at}` 저장·자동 재제출. 명단·큐·필터·KPI·상담 카드·CSV 전부 "설문 희망 OR 결과지 신청"으로 통일. 버튼은 "✓ 상담 신청됨"으로 전환 |

**요청 5의 설계 선택 — 사용자 확인 필요**: 설문 응답 `counsel_wish`는 배점 항목(희망 +5점, §2 Read-Only)이라 값을 직접
바꾸면 학생이 결과지를 본 **뒤에** JAS·Level이 달라질 수 있음. 그래서 응답값은 두고 별도 필드로 기록해 관리·상담 화면에서만
"상담 희망"으로 집계함. 응답값 자체를 바꾸는 방식을 원하면 1줄 변경으로 전환 가능(단, 결과지 재계산·재제출 동반).

**요청 4의 권고 절차**: ① 학생에게는 "같은 학번으로 다시 응시하면 갱신" 안내(반영) ② 상담사·마스터는 명단의 중복 의심 칩으로
주기적 확인 ③ 진짜 중복이면 잘못된 쪽을 "정보 수정"으로 학번 교정(응답·상담 기록 병합) 또는 마스터가 "응답 삭제".
제출 시점에 서버가 막는 방식은 학생(익명 인증)이 다른 응답을 읽을 권한이 없어 불가 — 학생 인증(§12-11) 도입 시 재검토.
