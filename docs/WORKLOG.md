## 2026-08-30 (마감 3) — Firebase 연동 구현 (별도 프로젝트, 설정 즉시 활성화)

결정: 기존 Firebase **계정**을 쓰되 **프로젝트는 분리**(`mjc-ready-pwa` 신규) — MJC-CAT Rules(익명
설계, 학번·이름 차단)와 실명 시스템이 상충하고, 공용 배포는 실서비스 리스크 (사용자 승인).
"별도 가입 대기"였던 보류 사유 해소 — 기존 계정에서 프로젝트만 추가하면 됨.

### 구현 (전부 폴백 구조 — config 비면 로컬 모드로 기존과 동일 동작)

- `src/lib/firebase.ts` — config 붙여넣는 곳(CLOUD_ENABLED 스위치) + `ready_*` 컬렉션 네임스페이스
- **학생 응답**: 결과지 도달 시 익명 인증으로 `ready_responses/{학기_학번}` 제출(재응시=본인 문서
  갱신), 성공 시 "응답이 안전하게 제출되었습니다" 표시
- **실측 데이터 소스**: 관리자·워크스페이스가 응답 있으면 실측 표시(원응답을 엔진으로 재판정 —
  결정론), 없으면 mock 미리보기 + 배너로 모드 구분 (`responsesSource.ts` useStudents)
- **상담 기록·등록부 공유**: localStorage를 캐시로 유지하며 Firestore write-through + 워크스페이스
  진입 시 최신 병합(`cloudStore.ts`) → 상담사 간 공유. 배너에 "☁ 공유 저장소 연결됨" 표시
- **교직원 인증 하이브리드**: 이메일 아이디+설정 완료 → Firebase Auth(가입→PENDING→승인) /
  그 외 → 기존 로컬 인증. 마스터는 콘솔 생성 계정(이메일 일치 판정), 비번 변경은 재설정 메일
- **Security Rules** (`firestore.rules`): 실명 응답 읽기=승인 교직원만, 상담 기록·등록부=상담사
  계열만(담당자 차단을 서버에서 강제!), staff 자가 승격 금지, 마스터=이메일 고정
- `docs/FIREBASE_SETUP.md` — 콘솔 설정 10분 가이드 (프로젝트 생성→config→Auth 2종+마스터 계정
  선점 생성→Rules 게시→승인 도메인)

| 담당자(행정, 구 일반 관리자) | `#/admin` | 종합 현황·명단·추천활동·다운로드만 |
